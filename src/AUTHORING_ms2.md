# 중학·고등 코스 2단계 — 학습용 완성 카드 작성 기준 (중1 = 한자검정 4급 313자부터)

## 목적
1단계(찾아보기용 기본 카드: 훈음·뜻·핵심 읽기·예시 단어)에 **초등 1,026자와 같은 수준의 학습 내용**을 채워
'오늘의 공부'에서 배울 수 있게 한다. 학습자: 한국인 성인 중심(어린이도 사용), 목표는 일본어를 실제로 읽는 것.
**정확성이 가장 중요하다.** 모르면 지어내지 말고 '학설이 여러 가지'·'불확실'로 솔직하게 쓴다.

**먼저 읽을 것(문체·밀도를 그대로 맞춤)**: `data/g3.js` 안의 아무 글자 몇 개(예: 集·進·都·薬)와 `src/AUDIT_MM.md`.
(g3.js 는 한 줄짜리 JS지만 `"k":"集"` 으로 찾으면 항목 하나를 볼 수 있다.)

## 입력
`원천데이터/ref/ref_g7_qN.txt` — 한 줄 = 한 글자, 탭으로 나뉜 세 칸:
1. 1단계 카드 JSON (k·hun·m·core·ex·t?) — 이미 검증된 것
2. 상용한자표 음훈 · 획수 · 부수 · KANJIDIC2 영어 뜻
   (칸 ②의 순서: 글자 | 획수 | 부수 | 음훈(괄호=드문 읽기) | 한국음 | 훈음 후보(libhangul) | 영어뜻 | 핵심 읽기 후보 | 흔한 단어 후보(표기·읽기·상용 읽기·영어))
3. 소리 가족 후보 — 같은 부품을 가지고 음독이 같은 초등 한자를 **기계적으로** 찾은 것.
   실제로 그 부품이 소리 부분일 때만 ad에 쓴다 (예: 歳의 '弋: 裁'는 우연의 일치라 쓰면 안 됨)

## 출력
`src/content_g7_qN.json` — 맡은 파일 **하나만** 만든다. 다른 파일·index.html·data/ 는 절대 건드리지 않는다.
`{"items":[ {완성 항목}, ... ]}` — 입력 순서 그대로, 빠짐없이.

## 완성 항목 형식
```json
{"k":"寝","hun":"잘 침","m":"자다, 눕다","e":"🛏️","t":"형성",
 "p":"宀(집) + 爿(침상) + 帚의 생략형(소리 シン)",
 "o":"집(宀) 안의 침상(爿)에서 쉬는 모습에 소리를 나타내는 부분을 더한 글자예요. 정자는 寢이에요.",
 "oc":"통설",
 "mm":"집(宀) 안 침상(爿)에 누워 쿨쿨 자요!",
 "ad":"정자 寢 → 일본 신자체 寝. 한국음 침(침실 寢室) ↔ 음독 シン. 寝る(ねる)는 '자다·눕다' 둘 다.",
 "tip":"자다는 ねる, 한자어는 しん (寝室 しんしつ)",
 "core":["ね-る","シン"],
 "ex":[["寝る","ねる","ね-る","자다"],["昼寝","ひるね","ね-る","낮잠"],["寝坊","ねぼう","ね-る","늦잠"],["寝室","しんしつ","シン","침실"]],
 "sp":[],
 "kr":[],
 "caution":[["寝坊","ねぼう","ね만 읽고 坊은 ぼう — 단어째 기억"]],
 "sent":[["日曜日は昼寝をします。","にちようびは ひるねを します。","일요일에는 낮잠을 잡니다.","昼寝"]],
 "confuse":[["浸","浸(잠길 침)은 왼쪽이 氵(물), 寝은 위가 宀(집)"]]}
```
(예시의 p·o 는 형식 설명용 — 寝의 실제 유래는 직접 확인해서 쓴다)

초등 완성 카드 실례 (data/g3.js, 이 밀도·문체를 그대로):
- 薬 `t:형성` `p:"艹(풀) + 楽(소리 ガク→ヤク) — 옛 글자 藥"` `o:"풀(艹)에 소리를 나타내는 樂(楽)을 더했어요. 옛날 약은 대부분 풀(약초)로 만들었어요."` `oc:확실` `mm:"풀(艹)을 먹었더니 즐거워(楽)졌어요 — 아픈 게 나았거든요!"` `ad:"일본 약자 薬 / 한국 정자 藥. 薬局(やっきょく)은 촉음화, 目薬(めぐすり)는 연탁. 楽(ラク·ガク)과 모양 비교."` `sent:["毎日薬をのみます。","まいにち くすりを のみます。","매일 약을 먹습니다.","薬"]`
- 都 `mm:"사람(者)이 가득한 큰 마을(오른쪽 阝 = 邑, 언덕이 아니에요) — 도읍!"` `kr:[["都合","한국어 '도합'(모두 합해)과 달리 사정, 형편 (都合がいい = 형편이 좋다)"]]` `caution:[["都合","つごう","사정·형편은 つごう — 都를 つ로 읽어요"]]`
- 起 `sent:["早起きは大切です。","はやおきは たいせつです。","일찍 일어나는 것은 중요합니다.","早起き"]` (동사는 활용하면 대상 단어가 문장에 그대로 안 들어가므로, 명사형 단어나 사전형이 그대로 들어가는 문장을 고른다)

## 필드 규칙
| 필드 | 규칙 |
|---|---|
| k·hun·m | 1단계 값 그대로. 틀렸다고 확신하면 고치고 보고에 적는다 |
| e | 뜻을 떠올리게 하는 이모지 1개 |
| t | `상형`/`지사`/`회의`/`형성`/`가차`/`회의 겸 형성`/`국자` 중 하나. 1단계에 `"t":"국자"`가 있으면 유지 |
| p | 구성 부품. 형성자는 반드시 `뜻 부분 + 소리 부분(소리 ○○)` 형태 |
| o | **진짜 유래** — 학계 통설만, 쉬운 해요체 1~3문장. 확실하지 않으면 "학설이 여러 가지예요". **지어낸 어원 금지**. 일본 신자체이면 정자를 함께 적는다(寝→寢, 歳→歲) |
| oc | `확실`/`통설`/`불확실` — o 내용과 일치 |
| mm | **외우기 이야기** 1~2문장, 쉬운 해요체·느낌표 톤. `AUDIT_MM.md`의 A~E 결함이 하나도 없어야 함 (부품 뜻은 그 글자 안에서 실제로 맡은 뜻, 없는 부품·가짜 분해 금지) |
| ad | 어른용 설명체 1~3문장: 정자 대응, 소리 가족(입력의 힌트 활용 — 같은 소리 부품의 초등 한자), 한국음↔음독 대응, 비슷한 한자 구별, 쓰임 뉘앙스 |
| tip | core 기준 "이럴 땐 이 발음" 한 줄 |
| core | 1~3개. 상용한자표 표기 그대로. 대표 음독 1개 + 대표 훈독 1개가 기본 (1단계 값 출발점) |
| ex | 3~6개 (흔한 단어가 없으면 1~2개 허용). 1단계 예시 유지 + 필요하면 보탬. core 읽기 단어 반드시 1개 이상. 형식 `[단어, 히라가나 읽기, 상용 읽기 표기, 한국어 뜻]` — 1단계와 같음(JMdict에 실제 있는 (표기, 읽기)만, 입력 ③칸 후보에서 고르면 안전). 다른 읽기도 맞는 단어(예: 一日 いちにち/ついたち)는 5번째 값 `1` |
| sp | 상용한자표 **부표(付表)** 특별 읽기 중 이 글자가 든 말만: `[단어, 히라가나 읽기, 한국어 뜻, 한 줄 설명]` (예: `["為替","かわせ","환, 환율","부표 특별 읽기 — 글자별로 나눠 읽지 않음"]`). 확신 없으면 `[]` |
| kr | 대표 단어 중 **한국에도 같은 한자어가 있는데 뜻이 다른 것**만: `[["단어","한국어 '○○'과 달리 ~라는 뜻"]]` |
| caution | 0~3개 `[단어, 히라가나 읽기, 한 줄 설명]` — 한자만 보고 예상하기 어려운 읽기. 단어에 이 글자 포함, 읽기는 히라가나만 |
| sent | **1개 필수** `[문장, 문장 읽기(히라가나, 띄어쓰기 허용), 한국어 번역, 대상 단어]` — 대상 단어는 ex에 있는 단어(가능하면 core 읽기 단어)이고 **문장 안에 글자 그대로** 있어야 하며, 문장 읽기(띄어쓰기 뺀 것)에 그 단어의 읽기가 그대로 들어 있어야 함. 짧고(25자 안팎) 일상적인 です·ます체. 문장 속 다른 한자는 초등 한자까지만, 그 밖은 히라가나로 |
| confuse | 0~2개 `[한자, 한 줄 차이]` — 모양이 실제로 비슷한 것만 |

## 검증 (반드시 실행)
```
cd C:\Users\GAUN\Documents\교육\일본어한자\src
python build_ms.py --check content_g7_qN.json
```
- **오류 0건, 경고 0건**이 될 때까지 고친다.
- INFO "예문 읽기 확인 필요"는 형태소 분석기와 다른 것 — 분석기가 틀리기도 하므로(明日→あす 등) **하나씩 직접 판정**해 내 읽기가 맞으면 둔다.
- 파일을 나눠 저장하며 진행해도 되지만, 끝났을 때는 하나의 올바른 JSON이어야 한다.

## 보고 (짧게, 한국어)

# 2차 콘텐츠 보강 지침 — "일본어를 읽기 위한 1026자"

목표: 한국인 학습자(성인 중심, 어린이도 사용)가 1026자를 **실제 일본어 속에서 읽고 이해**하게 한다.
핵심 질문: "이 한자는 무슨 뜻?"보다 **"일본 사람이 이 한자를 어떤 단어에서 어떻게 읽는가?"**
설계 문서: `DESIGN_v2.md` / 기존 원칙: `AUTHORING.md`, `AUDIT_MM.md` (그대로 유효)

## 작업 범위
각 항목(item)에 아래 필드를 **추가**하고 `ex`·`tip`을 다듬는다.
**건드리지 않는 필드**: k, hun, m, e, t, p, o, mm, ad, sp (이미 검수 완료)

## 입력 데이터
- `../일본어한자_원천데이터/freq/freq_gN.json` — 한자별
  - `cnt`: 읽기별 '흔한 말' 개수 (JMdict 공식 common 표시 기준)
  - `core`: 데이터가 제안한 핵심 읽기 (출발점일 뿐 — 아래 규칙으로 조정)
  - `cands`: 흔한 단어 후보 최대 40개 `{w 단어, y 읽기, r 이 한자의 읽기, nf 빈도순위(작을수록 흔함, 99=미상), g 단어 속 최고 학년(7=중학 이상), en 영어뜻}`

## 추가·수정 필드

### core — 핵심 읽기 (1~3개, 필수)
상용한자표 음훈 표기 그대로(`シ`, `よん`, `い-きる`). 기준:
1) 한자어에서 가장 많이 쓰는 **대표 음독** 1개(없으면 생략)
2) 단독 단어·기본 동사로 쓰는 **대표 훈독** 1개(없으면 생략)
3) 필요하면 1개 더. 데이터 `core`가 복합어 편중이면 고친다 (예: 上은 데이터상 あ-げる가 1위지만 기본은 うえ·ジョウ).

### ex — 대표 단어 4~7개 (재선정)
형식은 기존과 동일 `[단어, 전체 읽기(히라가나), 이 한자의 읽기 표기, 한국어 뜻, (선택)1]`.
- **흔한 말 우선**: `cands`의 nf가 작은 것, 학년 g가 낮은 것. 목표: 예시의 95% 이상이 JMdict 흔한 말.
- **core 읽기는 반드시 1개 이상 예시**로 보여준다. core 밖 읽기는 흔한 단어가 있을 때만.
- 기존 예시 중 좋은 것은 유지. 近郷·一朝一夕처럼 드문 말은 교체.
- 순서: core 읽기 단어 먼저 → 그 밖 순.
- 한국어 뜻은 짧게. 단어 자체가 한국어와 같으면 그대로(教室 → 교실).

### kr — 한국어와 뜻이 다른 한자어 (선택, 0개 이상)
`[["大変", "한국어 '대변(큰 변고)'과 달리 '힘들다·매우'라는 뜻"]]` — 대표 단어 중, **한국에도 같은 한자어가 있는데 뜻이 다른 것**만.
예: 手紙(편지), 勉強(공부), 大丈夫(괜찮다), 汽車(같음→표시 안 함), 新聞(같음), 留守(부재중), 丈夫(튼튼함), 心中(동반자살), 人間(인간 전체·사람), 工夫(궁리), 約束(같음), 無理(무리하다 뜻 범위 다름)
- 뜻이 거의 같으면 넣지 않는다. 한국에 없는 한자어도 넣지 않는다(그냥 새 단어).
- 설명은 한 줄: "한국어 '○○'과 달리 ~라는 뜻".

### caution — ⚠️ 주의할 읽기 (선택, 0~4개)
`[["四日", "よっか", "날짜 4일은 よっか"]]` — 한자 하나만 보고는 **예상하기 어려운 읽기**를 단어째 익히게.
- 대상: 숫자·날짜·세는 말의 불규칙(四日·四人·四時), 연탁·촉음이 예상 밖인 흔한 말, 한 글자 단독 읽기가 특수한 말.
- `sp`(상용한자표 부표 특별 읽기)와 중복하지 않는다(앱이 둘을 함께 보여줌).
- 설명은 한 줄. "왜"를 길게 설명하지 않는다.

### sent — 예문 1개 (필수)
`[["四月に日本へ行きます。", "しがつに にほんへ いきます。", "4월에 일본에 갑니다.", "四月"]]`
= `[문장, 문장 전체 읽기(히라가나, 띄어쓰기 허용), 자연스러운 한국어 번역, 대상 단어]`
- 대상 단어는 **ex에 있는 단어** 중 하나(가능하면 core 읽기 단어).
- 짧고(대략 25자 이내) 일상적인 문장. 어린이도 읽을 수 있게. です·ます체 기본.
- 다른 한자는 가능한 한 **같은 학년 이하** 한자로, 어려운 말은 히라가나로 써도 된다.
- 읽기는 문장 속 조사를 쓰인 대로(は·へ). 숫자는 한자로.
- 검증기가 형태소 분석기와 비교해 다르면 INFO를 낸다. 분석기는 **四月→よんがつ, 日本→にっぽん** 처럼 틀리기도 하므로, INFO마다 **직접 판정**해 내 읽기가 맞으면 두고, 틀리면 고친다. 보고서에 판정 결과를 남긴다.

### confuse — 헷갈리는 한자 (선택, 0~2개)
`[["末", "未는 위 가로획이 짧고(아직 미), 末은 위 가로획이 길어요(끝 말)"]]`
- 모양이 실제로 비슷해 혼동하기 쉬운 경우만. 1026자 밖 한자도 가능(曰 등). 한 줄.

### oc — 유래 신뢰도 (필수)
`"확실"` (학계 이견이 거의 없음) / `"통설"` (널리 받아들여지는 설) / `"불확실"` (o에 "학설이 여러 가지" 등)
- o의 내용과 일치하게. 앱에서 '불확실'은 "유래 확인 불충분" 배지로 보인다.

### tip — 한 줄 요령 (수정)
core 기준으로 "이럴 땐 이 발음"을 다시 쓴다. 예: "숫자는 よん·し, 4월은 しがつ, 날짜·사람 수는 단어째".

## 완성 예시 — 四 (content_g1.json)
core ["シ","よん"] / ex 四月·四角·四つ·四人·四日·四 / caution 四日 よっか·四人 よにん·四時 よじ /
sent 四月に日本へ行きます。 / confuse 西 / oc 통설

## 검증 (완료 조건)
`python build.py N` → **오류 0건, 경고 0건**. INFO 중 "흔한 말 표시 없음"은 최소화(필요 시 사유 보고), "예문 읽기 확인 필요"는 전부 직접 판정.
파일 하나를 끝낼 때마다 저장하고 검증한다(중단되어도 이어서 할 수 있도록).
